# 001 의심 점수 모델

## 배경

수신기는 둘레 Wi-Fi 기기의 프레임을 엿듣지만 내용은 암호화되어 볼 수 없다. 볼 수 있는 것은 겉모습뿐이다: 누가(MAC) 누구에게, 언제, 몇 바이트를 보냈나. 지금 수신기 코드(`receiver/firmware/core/score.py`)는 사람이 정한 규칙으로 증거를 더해 점수를 낸다 ([의심 점수 설계](../../docs/%EC%9D%98%EC%8B%AC%20%EC%A0%90%EC%88%98.md)). 규칙은 설명하기 쉽지만 경계값을 사람이 정해야 하고, 처음 보는 카메라에 약하다.

이 스펙은 같은 입력에서 '카메라일 가능성'을 내는 학습 모델을 만든다. 몰카(계속 영상을 보내는 카메라)와 시험 부정행위 카메라(가끔 사진을 보내는 카메라)를 **모드 구분 없이** 한 점수로 다룬다.

## 요구사항

| 번호 | 내용 |
|---|---|
| FR-1 | 입력: 기기(MAC) 하나의 30초 창. 프레임마다 (시각, 길이, 방향, 종류). 내용·주소는 쓰지 않는다 |
| FR-2 | 출력: 카메라일 확률(0~1)과, 점수에 가장 크게 기여한 특징 3개 (앱이 근거로 보여 준다) |
| FR-3 | 계속 보내는 카메라와 가끔 보내는 카메라(수 초~수십 초마다 사진 한 장)를 모두 양성으로 본다 |
| FR-4 | 자극 반응(걷기·조명에 전송량이 따라오는지)이 있으면 추가 특징으로 받는다. 없어도 동작한다 |
| FR-5 | 라즈베리파이 3B+ 에서 기기 30대를 1초 안에 채점한다 (파이토치 없이 돌릴 수 있게 내보낸다) |
| NFR-1 | 학습에 쓰지 않은 **기기 모델**로 평가한다 (같은 기기의 다른 날 데이터로 평가하지 않는다) |
| NFR-2 | 학습 데이터에 MAC 주소 원문을 남기지 않는다 (가명 처리) |

## 수용 기준

- 처음 보는 카메라 모델에서: 잘못 잡는 비율 5% 일 때 잡는 비율 90% 이상.
- 폰·노트북이 많은 곳(강의실 40명분 트래픽)에서 잘못 잡힌 기기 수가 평균 2대 아래.
- 규칙 기반 점수(기준선)보다 위 두 숫자 가운데 하나 이상이 낫고, 나머지는 나쁘지 않다. 아니면 규칙을 그대로 쓴다.

## 범위 밖

- 프레임 내용 해독. 블루투스·LTE 기기. 카메라 제조사·모델 알아맞히기.
