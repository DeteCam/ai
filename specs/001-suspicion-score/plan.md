# 001 의심 점수 모델 — 계획

## 데이터

| 종류 | 출처 | 쓰임 |
|---|---|---|
| 우리 카메라 | 실험용 카메라(초소형 2종 + 홈캠 1종)를 수신기로 직접 캡처: 정지 / 움직임 / 조명 / 사진 전송 주기별 | 양성 |
| 우리 기기 | 폰·노트북·태블릿·스마트 스피커의 평소 트래픽 (영상 통화, 스트리밍 시청, 클라우드 백업 포함) | 음성 (어려운 음성 포함) |
| 공개 데이터 | IoT 트래픽 공개 데이터셋 가운데 카메라가 든 것 (출처·라이선스는 `data/README.md` 에 적는다) | 양성·음성 보강, 처음 보는 기기 평가 |
| 합성 | 사진 전송 주기·크기, 비트레이트를 바꿔 가며 만든 가짜 흐름 (`receiver/sim/identify`) | 드문 경우 보강 |

캡처 원본(pcap)은 저장소에 넣지 않는다. 특징으로 바꾼 표(parquet)만 `data/` 에 두고, MAC 은 해시로 바꾼다.

## 특징 (30초 창)

올리는 바이트/초와 그 흔들림, 올림:내림 비, 프레임 길이 분포(MTU 근처 비율, 가운데값), 덩어리(burst) 크기·간격의 규칙성, 조용한 구간의 길이, 프레임 수 대비 바이트(뭉쳐 보내기), 자극과의 상관(있을 때), 처음 본 뒤 줄곧 켜져 있었나.

## 모델

1. **기준선**: 지금의 규칙 점수 (`score.py`).
2. **1차**: 그래디언트 부스팅 (특징 20개 안팎). 작고 설명하기 쉽고 파이에서 빠르다. 기여도는 SHAP 값 위 3개.
3. **2차 (1차가 모자랄 때만)**: 프레임 길이 시계열을 그대로 넣는 1D CNN.

모델은 순수 넘파이로 돌릴 수 있는 형식(트리 묶음 JSON)으로 내보내 `receiver/firmware/core` 가 읽는다.

## 평가

기기 모델 단위로 나눈 5겹 교차 검증 (leave-device-out). 지표: ROC, 잘못 잡는 비율 5% 에서의 잡는 비율, 혼잡한 곳에서 잘못 잡힌 기기 수. 기준선과 같은 데이터로 견준다.

## 위험

- 우리 카메라가 몇 대뿐이라 기기에 과적합한다 → 평가를 기기 단위로 나누고 공개 데이터로 보강한다. 그래도 안 되면 기준선을 쓴다.
- 클라우드 백업 중인 폰은 카메라와 닮았다 → 어려운 음성으로 일부러 모은다. 위치 측정 결과(책상 위인가)와 합쳐 최종 판단은 사람이 한다.
