# SPEC-002: 지도 반영 방향 · 위치 추정과 측정 뒤 절차

- 상태: 명세 · 시뮬레이션 단계 (실측 전). 마지막 수정 2026-11-27
- 기준: [docs/AGENTS.md](https://github.com/DeteCam/docs/blob/main/AGENTS.md) G2 · G3 · G4, 4장, 5장(시뮬레이션 규칙), 7.3 · 7.4절
- 수신기: [receiver SPEC-002](https://github.com/DeteCam/receiver/blob/main/specs/002-switch-ring-receiver/spec.md) (지름 12 cm 16소자 고리 + 기준 안테나, 끄덕이는 머리, 1기를 여러 자리로)
- 설명과 근거 표: [`docs/알고리즘_설계.md`](../../docs/알고리즘_설계.md)

## 1. 무엇을, 왜

작은 수신기 하나가 한 자리에서 잰 방향은 반사와 가림 때문에 크게 틀릴 수 있다. 그래서 ① 반사를 지우지 않고 방 지도로 계산해 함께 맞추고, ② 여러 자리에서 잰 지도를 합쳐 위치를 먼저 구한 뒤 방향을 내고, ③ 믿기 어려운 측정을 가려내고, ④ 모자라면 자리를 더 재라고 안내한다. 수신기 구조를 키우는 대신 이 절차로 오차를 줄인다(R4).

## 2. 처리 단계

| 단계 | 내용 | 입력 | 출력 |
|---|---|---|---|
| S1.5 스위치 상태 짝짓기 | 받은 패킷이 고리의 어느 소자에서 왔는지 정한다. 스위치는 17상태(소자 16 + 모두 끔)를 돌고, 한 상태에서 패킷 5개(모두 끔은 3개)를 모으면 바로 넘어간다(적응 전환). 전환 앞뒤 10~20 ms의 패킷은 버린다. 모두 끔 상태는 체인 B ÷ 체인 A가 앵커 값과 같아지는 것으로 알아보고, 이것으로 무선랜 카드 시각과 스위치 주기의 어긋남을 맞춘다 | 두 단자 CSI, 패킷 시각(무선랜 카드 · 호스트), 스위치 전환 시각 | 패킷마다 소자 번호(또는 버림) |
| S2 위상 기준 맞추기 | 체인 B ÷ 체인 A, 스윕 패킷의 기준 세기 가중 켤레곱 평균, 앵커로 패킷마다 부호 복원, "센 쪽 = 기준 체인"으로 체인 가르기 | 두 단자 CSI, 포트 번호 | 소자별 복소 응답 |
| S3 간섭 보정 | 16소자 + 기준 안테나 보정표 적용(유전체 면용 · 금속면용). 끄덕일 때 고리 중심이 옮겨 가는 것(축이 상자 가운데에 있어 ±20°에서 약 4 cm)을 자세마다 넣는다. 보정표는 케이블 배선과 스위치의 꺼진 포트 상태까지 담은 실물 표를 쓴다(채널 1 · 6 · 11에서 표가 다르면 채널별 표) | 한 번 만든 보정표, 끄덕인 각도, 축 자리 | 보정된 응답 |
| S4-1 자리마다의 우도 지도 | 방 안 후보 위치마다 직접파 + 벽 · 천장 · 바닥 반사(1차 · 2차)를 계산해 잰 값과 맞춤. 끄덕인 세 자세의 지도를 더함 | 방 크기, 수신기 위치 · 각도(폰 AR) | 자리 지도, 지도 퍼짐 |
| S4-2 여러 자리 합치기 | 자리 지도를 같은 좌표에서 더해 위치를 구함 | 자리 지도 2개 이상 | 위치, 합친 지도 퍼짐 |
| S4-3 융합 방향 | 지도 퍼짐이 가장 작은 자리에서 합친 위치를 바라본 방향 | 위치, 자리별 퍼짐 | 방향 |
| S5 현장 보정 | 위치를 아는 송신기 한두 개로 수신기가 놓인 각도를 맞춤 | 송신기 측정 | 각도 보정값 |
| S6 신뢰도 · 의심 구역 | 자리 지도 퍼짐이 문턱보다 크면 "믿기 어려움"으로 표시(표준: 퍼짐 규칙, 후보: 배운 모델). 합친 지도로 AR 의심 구역을 만듦 | 자리 지도, 합친 지도 | 신뢰도, 구역 |
| S9 측정 안내 | 합친 지도 퍼짐이 문턱보다 크면 자리를 더 재라고 안내("더 재기") | 합친 지도 퍼짐 | 계속 / 멈춤 |
| 시험실 | 폰 AR이 찾은 책상 후보 위에서 의심 책상 3곳을 냄. 좌석 정보는 미리 입력하지 않음(R10) | 책상 후보, 합친 지도 | 의심 책상 3곳 |

문턱(자리 지도 퍼짐 13.87°, 합친 지도 퍼짐 0.417 m)은 개발용 방에서 정했고 평가용 방에서는 바꾸지 않는다.

## 3. 요구사항

| 번호 | 요구사항 | 수용 기준 | 확인 |
|---|---|---|---|
| FR-1 | 방향 정확도 (G2) | 같은 방 · 자리 · 날에 DiffLoc 재현 장비보다 평균 방향 오차가 3° 이상 작고 95% 지점도 작다(2.4 GHz 비교, 5 GHz는 따로 보고). 한 번 잰 방향과 융합 방향을 나눠 적는다 | V1 계산 뒤 V4 실측 (AGENTS.md 7.3) |
| FR-2 | 위치 (G4) | 시험실 밖: 공간 종류마다 카메라의 80% 이상을 0.5 m 안에. 시험실: 한 칸씩 띄운 자리에서 진짜 책상이 의심 책상 3곳 안에 80% 이상 | V1 계산 뒤 V4 실측 |
| FR-3 | 의심 구역 (G3) | 실제 카메라를 포함하는 비율 90% 이상, 구역 크기를 함께 보고 | V6 실측 (AGENTS.md 7.4) |
| FR-4 | 신뢰도 | 믿기 어려운 측정을 표시하고 다른 자리에서 다시 재라고 안내한다. 가려낸 비율과 남긴 측정의 오차를 함께 보고한다 | V1 계산 뒤 V4 실측 |
| FR-5 | 측정 안내 | 합친 지도가 퍼져 있으면 자리를 더 재라고 안내하고, 잰 자리 수를 함께 보고한다 | V1 계산 뒤 V4 실측 |
| FR-6 | 실패를 숨기지 않기 | CSI를 못 얻은 경우(802.11b 등), 측정 실패, 믿기 어려움으로 가린 횟수를 빼지 않고 보고한다 | V1 · V4 · V6 |
| FR-7 | 학습 모델 채택 조건 | 단순 규칙과 같은 평가에서 견주고, 배운 방과 다른 방에서 평가한다. 미리 적은 기준을 넘을 때만 표준으로 올린다. 시뮬레이션 지도로 배운 모델을 실물에 처음 넣을 때는 측정을 가려내는 데만 쓰고, 추정값을 바꾸는 모델은 실측 지도로 다시 배우고 평가한 뒤에 넣는다 | 계획서와 결과 문서 |
| FR-8 | 스위치 상태 짝짓기 | 다른 소자 것으로 잘못 짝지은 패킷이 5% 이하(교정 현실 조건 계산이 가정한 값). 버린 패킷 비율과 한 자세에 걸린 시간을 함께 보고한다 | 계산(몬테카를로) 뒤 벤치: 알려진 송신기로 포트 순서 확인 |
| FR-9 | 같은 형식의 패킷끼리 묶기 | 한 번의 스윕에는 같은 대역 · 채널 폭 · 프레임 형식의 패킷만 쓴다. CSI가 나오지 않는 프레임(802.11b 등)은 세어서 보고한다(FR-6) | 코드 검토, 벤치 |
| NFR-1 | 계산 시간 | 수신기 호스트(CM4)에서 카메라 하나의 추정이 5초 이하. 추정값은 시험실 밖 약 0.2초, 시험실 0.8~1.4초 | 실측 |
| NFR-2 | 입력 제한 (R10 · R11) | 좌석 배치도 · 응시자 자리 · 책상 좌표를 미리 받지 않는다. 좌석마다 둔 기기의 값을 쓰지 않는다 | 코드 검토 |

## 4. 사전 검증 근거 (시뮬레이션 계산값 — 실측 아님, AGENTS.md 5.4절)

- 도구: Sionna RT 2.2.0(반사 4회, 회절, 투과, 난반사) + PyNEC 2.4.1. 계획서 · 코드 · 결과는 [receiver/sim](https://github.com/DeteCam/receiver/blob/main/sim/README.md)에 있다.
- 기존 방 17개(2.4 GHz): 한 자리 방위각 평균 8.4°, 벽 4곳 0.5 m 안 80%(종류별 72~85%).
- 실제와 비슷한 새 방 16개(2.4 GHz 설계 조건, 세 묶음):
  - 한 번 잰 방향 평균 13.8~16.3°, 중앙값 4.2~4.9° → FR-1 기준선(8.92°) 미달
  - 융합 방향(4자리) 평균 4.4~5.4°, 95% 지점 12.5~16.8° → 기준선 통과(묶음 C는 기준을 미리 적고 확인)
  - 위치 0.5 m 안, "더 재기"(평균 5.1~5.6곳): 숙박 81~88%, 합판 칸막이 화장실 79~89%, 탈의실 72~77%, 금속 칸막이 화장실 49% → 숙박은 통과, 탈의실과 금속 칸막이 화장실은 미달
  - 시험실 의심 책상 3곳 안: 앞벽 두 자리 88~93%, 한 자리 38~61%
  - 5 GHz(묶음 A · B 설계 조건): 한 번 잰 방향 13.3~14.0°, 융합 방향 4.4°(묶음 B)
- 교정한 현실 조건(체인 뒤바뀜 · 수신 세기 자동 조절 · 누설 · 보정 오차 등을 넣음): 한 번 잰 방향 14.5~17.4°, 융합 방향 4.9~5.3°, 시험실 앞벽 두 자리 75~88%(계단식 강의실 1곳 미달).
- 처음 미리 적었던 현실 조건은 체인 판정 규칙이 거꾸로 동작해 방향 23.6°로 무너졌다. 체인 B 입력 감쇠기와 새 규칙으로 고쳤고, 고친 조건은 "사후 추가"로 표시한다.
- 미리 적은 예상 10개 가운데 4개는 맞았고, 3개는 틀렸고, 3개는 일부만 맞았다.
- 스위치 상태 짝짓기(2026-11-27, 몬테카를로 계산값, [위험 점검 결과](https://github.com/DeteCam/receiver/blob/main/sim/위험-점검-결과.md)): 호스트 시각만 쓰고 가드 없이 60 ms씩 머물면 시각 흔들림이 나쁠 때 6.5~7.2%를 잘못 짝짓는다(기준 5% 미달). 100 ms 이상 머물고 앞뒤 10 ms를 버리면 1.7%다. 적응 전환(5개 모으면 넘어감, 가드 10 ms)은 4.7% 이하이고 한 자세에 초당 26패킷 카메라 기준 3.4초(99% 지점 4.3초), 초당 10패킷이면 8.5초가 걸린다. 시각 흔들림 값은 가정이라 벤치에서 다시 잰다.
- 꺼진 포트가 50 Ω으로 끝나지 않는 스위치(반사형)인 경우(2.4 GHz 계산값): 실물 보정표가 그 상태를 담으면 한 번 잰 방향 +0.8~1.9%, 융합 방향 4.4° → 5.0~5.3°. 모형 표만 믿으면 한 번 잰 방향 +6.5~6.7%, 위치 −4~−9%p다. 그래서 보정표는 실물에서 만들고 채널에 따라 달라지는지 본다.

## 5. 범위 밖

- 한 자리 측정만으로 방향을 확정하는 것(가려진 카메라에서 크게 틀림)
- 다음에 잴 자리를 자동으로 고르는 것(아직 없음, 미리 정한 순서로 잼)
- 802.11b(DSSS) 프레임의 방향 추정(CSI가 나오지 않음)
- 카메라 높이를 정밀하게 맞히는 것
