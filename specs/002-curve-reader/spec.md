# 002 CSI 곡선 판독 모델

## 배경

수신기는 알루미늄 판을 한 바퀴 돌리며 판 각도마다의 신호 세기를 잰다. 이 곡선에서 카메라 방향을 읽는 방법이 정확도를 좌우한다.

- **골 찾기** (가장 깊이 꺼진 곳의 가운데를 읽는다): 수신기 자기 부품이 곡선 모양을 바꾸면 크게 틀린다. 전파 계산으로 만든 곡선에서는 방향 오차 가운데값이 45° 를 넘었다.
- **곡선 전체 맞추기** (후보 방향마다 '보였어야 할 곡선'과 견준다): 같은 조건에서 3~7°. 40명이 앉은 교실에서도 자리를 맞힌다 ([검증 보고서](https://github.com/DeteCam/docs/tree/main/verification)).

곡선 전체 맞추기는 직접파 하나만 가정한다. 실제로는 벽·천장·사람에게서 온 반사파가 섞인다. 이 스펙은 **반사가 섞인 곡선까지 학습한 모델**로 곡선 전체 맞추기(기준선)를 넘어서는 것을 목표로 한다.

## 요구사항

| 번호 | 내용 |
|---|---|
| FR-1 | 입력: 한 곳에서 잰 스캔 묶음. 스캔마다 [판 각 72칸 × 서브캐리어 52개] 세기와 그 스캔의 자세(받침 각, 숙임 각) |
| FR-2 | 출력: 후보 점(방 안의 칸 또는 자리)마다의 로그 점수. 기준선과 같은 꼴이라 위치 계산(`locate`)에 그대로 꽂힌다 |
| FR-3 | 학습 데이터는 시뮬레이션(`receiver/sim/rt`: 광선 추적 + 수신기 무늬 표)으로 만들고, 실물로 잰 곡선으로 미세 조정한다 |
| FR-4 | 수신기(라즈베리파이 3B+)에서 한 곳(스캔 18번)을 2초 안에 계산한다 |
| NFR-1 | 평가는 학습에 쓰지 않은 **방**과 **사람 배치**로 한다 |
| NFR-2 | 모델이 내는 점수가 지나치게 자신 있지 않아야 한다 (후보 3자리 확률 합과 실제 맞는 비율의 차이 10%p 안) |

## 수용 기준

- 학습에 쓰지 않은 교실 시뮬레이션에서, 기준선(곡선 전체 맞추기)보다 '자리를 정확히 맞히는 비율'이 5%p 이상 높다. (기준선 숫자는 검증 보고서의 표)
- 실물 검증 묶음(트인 곳 + 교실, 방향을 아는 카메라)에서 기준선보다 나쁘지 않다.
- 둘 가운데 하나라도 못 미치면 모델을 넣지 않고 기준선을 쓴다.

## 범위 밖
