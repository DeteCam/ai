# 알고리즘 설계

- 상태: 설계. 실측 전. 2026-11-24
- 기준: [docs/AGENTS.md](https://github.com/DeteCam/docs/blob/main/AGENTS.md) 4장

## 1. 문제

1. **카메라만 골라내기**: 암호화된 Wi-Fi에서 패킷 내용은 볼 수 없다. 영상 통화 · 라이브 방송 기기는 카메라와 보내는 모양이 비슷하다.
2. **작은 수신기의 방향 재기**: 지름 약 10 cm 고리는 2.4 GHz 파장(12.3 cm)과 비슷한 크기라 방향 분해능이 낮다. 채널 폭 20 MHz로는 방 안 반사를 시간으로 가를 수 없다. 오차의 대부분은 잡음이 아니라 반사에서 온다.
3. **사람과 가구**: 사람 몸이 직접파를 가리면 어떤 계산으로도 방향이 흐려진다.

## 2. 방법

### 2.1 카메라 판별 (S1)
규칙 기준선(업로드 비율, 자극 구간과 전송량 변화의 상관) → 실제 캡처로 로지스틱 회귀 → 작은 신경망. 앞 단계보다 나을 때만 다음 단계를 쓴다. 평가는 기기 단위로 나눈다.

### 2.2 위상 기준과 간섭 보정 (S2 · S3)
고리 안테나 CSI를 기준 안테나 CSI로 나눠 패킷마다 바뀌는 위상 · 시각 오차를 지운다. 고리가 대칭이므로 집에서 수신기를 회전 받침에 올려 한 번 잰 응답을 각도만 돌려 8개 안테나에 쓴다.

### 2.3 지도 반영 추정 (S4)
벽은 거울과 같아서 벽에 튕긴 전파는 벽 너머의 '거울 속 카메라'가 보낸 것처럼 보인다. 후보 위치마다 직접파와 거울 속 위치 18개(한 번 반사 6, 두 번 반사 12)에서 온 신호 모양을 계산하고, 경로별 세기 · 위상은 측정값에 맞춰 푼다(능형 회귀). 직접파가 가려진 가설도 함께 두고 섞는다. 벽 뒤 방향은 처음부터 뺀다.

근거: 다중경로 보조 위치 추정(Witrisal 외, IEEE SPM 2016), 수신기 하나로 반사를 써서 위치를 찾은 MonoLoco(MobiSys 2018).

### 2.4 현장 보정 (S5)
위치를 아는 송신기 몇 곳의 측정으로 수신기 방향각 · 위치 · 방 크기를 최적화한다(넬더-미드, 사전 분포 포함).

### 2.5 신뢰도와 의심 구역 (S6)
가능성 지도에서 방위각 분포의 퍼짐을 신뢰도로 쓴다. 퍼짐이 크면 "다른 모서리에서 다시"를 안내한다. 두 자리 이상의 가능성 지도를 더해 AR 구역을 만든다. 구역 포함률은 실측으로 보정한다.

## 3. 시도했지만 쓰지 않는 것 (시뮬레이션, 2026-11-24)

| 방법 | 결과 |
|---|---|
| 학습으로 가능성 지도 봉우리 가운데 진짜 고르기 | 다른 방에서 이득 없음 (교실 9.8° → 9.9°) |
| 학습 신뢰도 | 방향 분포 퍼짐과 같거나 못함 |
| 직접파 보임 판별 학습 | 구분 능력 0.56~0.64 |
| 송신기로 벽별 반사 세기 학습 | 오히려 나빠짐 (두 자리 1 m 이내 82% → 64%) |
| v6 ReconCovNet · MA-PINN · CamGuard-Net | 같은 시뮬레이터로 학습 · 평가해 독립 검증에서 이득 확인 안 됨 (receiver 브랜치 `archive/v6-nano2`) |

## 4. 한계

전파를 내지 않는 카메라는 찾지 못한다. 직접파가 가려진 자리에서는 방향이 흐려지므로 결과를 "의심"과 확률로 보여 준다.
