# 알고리즘 설계

- 상태: 문서 조사와 시뮬레이션 단계 · 실측 전 (2026-11-26)
- 기준: [docs/AGENTS.md](https://github.com/DeteCam/docs/blob/main/AGENTS.md) 4장(소프트웨어 · AI 원칙), 현재 구성은 [docs/현재_방향.md](https://github.com/DeteCam/docs/blob/main/현재_방향.md) 2절
- 방향 · 위치 숫자는 모두 **시뮬레이션 계산값**이다(Sionna RT + NEC2, 2.4 GHz 설계 조건, 실제와 비슷한 새 방 16개). 전체 표는 [receiver/sim/실제-방-시뮬레이션-결과.md](https://github.com/DeteCam/receiver/blob/main/sim/실제-방-시뮬레이션-결과.md)에 있다.

## 1. 문제

1. **카메라만 골라내기 (G1).** 암호화된 Wi-Fi에서 패킷 내용은 볼 수 없다. 시험장에서는 조명을 바꾸거나 걸어 다니는 자극을 쓸 수 없고, 영상 통화 · 라이브 방송 기기는 카메라와 트래픽 모양이 비슷하다.
2. **작은 수신기로 방향 재기 (G2).** 지름 12 cm 고리는 2.4 GHz 파장(12.3 cm)과 비슷한 크기라 빔 폭이 넓다. 채널 폭 20 MHz로는 방 안 반사를 시간으로 가를 수 없다.
3. **AX210의 위상 특성.** 패킷마다 위상이 180° 뒤집힐 수 있고, CSI 두 행이 어느 단자 것인지 알려 주지 않는다. 이것을 풀지 않으면 방향 추정이 무너진다.
4. **가림.** 카메라와 수신 자리 사이가 가구 · 칸막이 · 사람에 가리면 한 자리에서 잰 방향이 크게 틀린다. 새 방 16개 계산에서 가린 경우(36%)는 평균 25.4°, 안 가린 경우는 7.4°였다. 20°를 넘는 큰 오차 17%가 평균 오차의 71%를 만든다.
5. **수신기는 1기.** 여러 자리에서 잰 값은 같은 순간의 값이 아니다. 시험실에서는 자리를 옮기는 동안 카메라가 송출을 멈출 수 있다.

## 2. 방법

### 2.1 카메라 판별 (S1)

- 활성 채널을 빠르게 훑은 뒤(1~3초), 패킷 내용을 풀지 않고 프레임 메타 정보만으로 판별한다: 주소 쌍마다의 올림 · 내림 비대칭(카메라가 공유기 역할을 하는 경우 포함), 20 ms 프레임 묶음, 100 ms 단위 바이트율의 주기, 1초 연속성, 무선 능력 정보(안테나 수, 채널 폭), 카메라와 핫스팟 짝짓기, 입실 전 기준선과 견준 새 기기 여부.
- 자극 반응(조명 · 움직임)은 시험실 밖에서만 쓰는 보조 증거다.
- 모델은 규칙 → 로지스틱 회귀 → 얕은 경사 부스팅 → 작은 신경망 순으로, 기기 단위로 나눈 같은 평가에서 견준다(AGENTS.md 4장). 공개 실측 데이터 사전 검증([`eval/PUBLIC_LODO_RESULTS_20261125.md`](../eval/PUBLIC_LODO_RESULTS_20261125.md))에서 작은 신경망은 학습 기기에 과적합해 탈락했고, 얕은 경사 부스팅과 로지스틱 회귀가 가장 나았다. 최종 판정은 실제 기기 캡처(2.4 · 5 GHz 각각)로 한다.

### 2.2 위상 기준 맞추기 (S2)

1. **비율.** 체인 B(스위치로 고른 고리 소자 + 앵커) ÷ 체인 A(기준 안테나)로 패킷마다 달라지는 공통 위상을 지운다. 스윕 패킷은 기준 신호 세기로 가중한 켤레곱 평균으로 합친다. 단순 비율 평균은 기준 안테나가 약해지는 순간 잡음이 커져 더 나빴다(11-25 계산).
2. **부호 복원.** 기준 신호의 사본(앵커)을 체인 B에 알려진 비율로 섞어 패킷마다 ±1 부호를 되찾는다. 지금 배치(H4: 윌킨슨 분배기 2개 + 스위치 공통 포트 뒤 6 dB 감쇠기)에서는 앵커가 고리 신호보다 약 6 dB 세다. 계산값 부호 복원 97%.
3. **체인 가르기.** AX210 체인 B 입력에 6 dB 감쇠기를 달아 기준 체인이 늘 더 세게 들어오게 하고, CSI 두 행 가운데 "센 쪽 = 기준 체인"으로 가른다. 예전 규칙("센 쪽 = 스위치 체인")은 H4 배치에서 거꾸로 동작했다(틀린 패킷 78%, 방향 평균 35°). 새 규칙은 틀린 패킷 4%, 방향 13.1°(뒤바뀜이 없을 때 13.0°). 전제(AX210이 CSI 행을 세기 순으로 냄)는 벤치에서 확인한다.

### 2.3 간섭 보정 (S3)

- 고리 16소자 + 가운데 기준 안테나를 한 배열로 보고, 안테나끼리의 간섭과 스위치 포트 차이를 보정표 하나에 담는다. 집에서 한 번 만들고 현장에서는 돌리지 않는다.
- 놓는 곳 가까이의 면이 소자 위상을 바꾸므로 유전체 면용과 금속면용 보정표를 따로 둔다.

### 2.4 자리마다의 지도 반영 우도 지도 (S4)

- 방 안 후보 위치마다 직접파와 벽 · 천장 · 바닥 반사(1차 6개, 2차 12개 거울상)가 수신기에 만드는 응답을 계산하고, 잰 CSI와 얼마나 맞는지를 우도로 매긴다. 부반송파 전체를 함께 쓰고, 이상값에 덜 흔들리도록 큰 잔차를 눌러 준다.
- 끄덕인 세 자세(−20° · 0° · +20°)의 지도를 더한다.
- 추정기가 쓰는 방 정보는 사용자가 실제로 알 수 있는 것(벽 · 천장 · 바닥 위치, 수신기 위치 · 각도)뿐이다. 가구나 지도에 없는 금속은 모른다.
- 벽 반사를 지도에서 빼면 방향 오차가 32% 커진다. 1차 반사만 쓰면 4.7% 커진다.

### 2.5 여러 자리 합치기와 "융합 방향" (S4)

- 자리마다의 우도 지도를 같은 좌표에서 더해 위치를 구한다. 자리 사이에 시각을 맞출 필요가 없어 1기를 차례로 옮겨 재도 된다.
- **방향은 한 자리 지도에서 바로 읽지 않는다.** 합친 지도에서 위치를 먼저 구하고, 지도 퍼짐이 가장 작은 자리에서 그 위치를 바라본 방향을 낸다.

| 방향 보고 방식 (4자리, 평균 / 95% 지점) | 묶음 A | 묶음 B | 묶음 C |
|---|---|---|---|
| 한 자리에서 한 번 잰 방향 | 13.8° / 72.5° | 16.3° / 81.8° | 14.0° / 65.8° |
| 가장 믿을 만한 자리의 자기 방향 | 6.1° / 26.7° | 7.4° / 27.9° | 7.5° / 38.4° |
| 융합 방향 | 4.4° / 12.5° | 5.3° / 16.8° | 5.4° / 15.8° |

- 융합 방향은 묶음 A · B의 결과를 본 뒤 떠올린 것이라, 새 방 5개(묶음 C)에 판정 기준을 미리 적고 다시 계산해 확인했다. 비교 기준선은 평균 8.92° 이하, 95% 지점 27.53° 미만이다.
- 방 하나씩 보면 금속 칸막이 화장실(9.9° / 31.6°)과 수영장 탈의실(8.9° / 47.5°)은 기준선 밖이다.

### 2.6 신뢰도 (S6)

- **표준: 퍼짐 규칙.** 한 자리 지도의 방위각 퍼짐이 문턱(13.87°, 기존 방 17개에서 정함)보다 크면 "이 자리는 믿기 어렵다"고 알린다.
- **후보: 배운 모델.** 지도에서 뽑은 26개 값으로 경사 부스팅 모델이 "20° 넘게 틀렸을 가능성"을 낸다. 기존 방 17개에서 배우고 새 방 16개에서 평가했다.

| 20° 넘는 오차 가려내기 (AUC) | 묶음 A | 묶음 B | 묶음 C |
|---|---|---|---|
| 퍼짐 규칙 | 0.740 | 0.750 | 0.720 |
| 배운 모델 | 0.797 | 0.826 | 0.779 |

- 믿을 만한 60%만 남기면 한 번 잰 방향 평균이 규칙 7.3~8.2°, 배운 모델 6.9~7.3°가 된다(전부 쓰면 13.8~16.3°).
- 배운 모델이 세 묶음 모두에서 낫지만, 미리 적은 기준 하나(가장 믿을 만한 자리의 방향 95% 지점)를 1.3° 차이로 못 넘어 표준으로 올리지 않았다. 시뮬레이션 지도로 배운 모델이 실물 지도에서도 통하는지는 실측 지도가 생긴 뒤 다시 학습 · 평가해 정한다.

### 2.7 측정 안내 "더 재기" (S9)

- 합친 지도의 퍼짐이 0.417 m(기존 방에서 정한 문턱)보다 크면 자리를 하나 더 재라고 안내하고, 작아지면 멈춘다.

| 0.5 m 안 (숙박 / 화장실 / 탈의실) | 묶음 A | 묶음 B | 묶음 C |
|---|---|---|---|
| 4자리 고정 | 69.6 / 65.8 / 66.7% | 79.6 / 49.2 / 61.7% | 62.5 / 85.8 / 68.3% |
| 더 재기 (평균 자리 수) | 87.5 / 79.2 / 75.0% (5.6곳) | 83.3 / 49.2 / 71.7% (5.1곳) | 81.2 / 89.2 / 76.7% (5.6곳) |

- 다음에 잴 자리를 고르는 기능은 아직 없다. 지금은 미리 정한 순서대로 잰다.

### 2.8 시험실: 의심 책상 3곳

- 좌석 배치는 미리 입력하지 않는다(R10). 폰 AR이 현장에서 찾은 책상 후보 위에 합친 지도를 올려 의심 책상 3곳을 낸다. 계산은 책상 인식 오차 0.10 m를 가정했다.
- 앞벽 두 자리를 모두 재면 진짜 책상이 3곳 안에 88~93%(설계 조건), 한 자리만 남으면 38~61%다. 두 자리가 필요하다.

### 2.9 현장 보정 (S5)

- 위치를 아는 송신기(폰 등) 한두 개로 수신기가 놓인 각도를 맞춘다. 이전 계산에서 각도 6° 오차를 0.6~1.5°로 줄였다(지금 시뮬레이션 기준이 생기기 전 값이라 참고로만 쓴다). 좌석마다 두는 기기가 아니다(R11).

## 3. 시도했지만 쓰지 않는 것 (AGENTS.md 5.1절 10번)

| 방법 | 결과 |
|---|---|
| 작은 신경망으로 카메라 판별(공개 실측, 기기 분리) | 학습 기기에 과적합. 얕은 경사 부스팅 · 로지스틱 회귀보다 크게 나쁨 |
| 단순 비율 평균 `mean(H_m / H_ref)` | 기준 안테나가 약해지는 순간 잡음이 커져 켤레곱 평균보다 5 GHz 2자리 95% 지점이 13.6° 나쁨(11-25 계산) |
| 칠판 · 거울 · 사물함 면을 지도에 더 넣기 | 11-25 계산에서 0.1~0.4° 나빠짐, 11-26 새 방에서 −1.3%(차이 없음) |
| 체인 판정 "센 쪽 = 스위치 체인" | 앵커 배치 H4에서 거꾸로 동작(틀린 패킷 78%) |
| 끄덕인 세 자세의 위상까지 맞춰 합치기 | 한 번 잰 방향 +7.5%(나빠짐) |
| 높이 5층 격자 | +0.7%(차이 없음) |
| 지도 잘라내기 · 신뢰도 가중 · 나쁜 자리 빼기 융합 | 4자리 0.5 m 안 67.9% → 최대 69.2%(차이 없음) |
| 신뢰도가 낮으면 자리를 옮겨 그 자리 방향을 쓰기 | 평균 7.3~8.9°, 95% 지점 31~44°로 융합 방향보다 나쁨 |
| 학습으로 지도 봉우리 고르기 · 직접파 판별 · 벽별 반사율 학습(11-24) | 다른 방에서 이득 없거나 나빠짐 |
| 제곱으로 180° 뒤집힘 없애기 | 반사가 하나만 있어도 오차 27~66°로 무너짐 |
| v6의 학습 모델들 | 같은 시뮬레이터에서 학습 · 평가한 값이라 독립 검증에서 이득 없음 |

## 4. 한계

- 전파를 내지 않는 카메라(SD 카드 저장형)는 찾지 못한다.
- 한 자리에서 한 번 잰 방향은 기준선을 넘지 못했다(13.8~16.3°). 여러 자리를 합쳐야 한다.
- 금속 칸막이 화장실(위치 45~49%)과 금속 사물함 탈의실(68~79%)은 자리를 늘려도 목표(80%)에 못 미쳤다.
- 2.4 GHz 카메라가 802.11b(DSSS)로 떨어지면 CSI가 나오지 않는다. 탐지는 되지만 방향은 낼 수 없어 화면에 그렇게 알린다.
- 얇은 유리 뒤 카메라, 신호가 약해 패킷을 못 받는 경우, 사진만 가끔 보내는 카메라의 패킷 수는 시뮬레이션이 다루지 못했다. 실물로 확인한다.
- 위 숫자는 설계를 고르는 근거일 뿐 실물 성능이 아니다.
